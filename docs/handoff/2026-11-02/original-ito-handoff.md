予約と同伴者登録：確定の意味を揃える
基本の操作順【確認】
日付・コース選択 → スタート枠と人数を選択 → 予約内容・料金を確認 → 自分で同意チェック → 予約確定
→ 同伴者を登録、または後で登録 → 予約一覧。変更時は既存予約をもとに選び直します。
重要仕様
実装・引き継ぎポイント
複数組を１件に集約
各組には個別id、まとめた予約にはbatchIdを持つ。トップや一覧の「件数」は予約グループ
数。組数と人数は別に表示。
本人の参加枠
memberPlayingとownerKeyで、本人が参加する枠を識別。紹介枠は本人未同伴。人数から同
伴者数を求める際にこの違いを使う。
同伴者は後でも登録
予約完了と同伴者登録完了を分ける。「あとで登録する」から一覧へ進める。複数組の登録は
残りの組へ順に進める。
「未定」の明示操作
未選択と未定を区別。残り人数に応じて表示を変え、未定を選択して登録できる。後から名前
を登録する入口も用意。
重複防止
組内・組をまたぐ同名登録を検査。別組で登録済みの人を表示し、「未定」は重複扱いしない。
メンバータイム
本人１名という特性を維持。同伴者編集を通常予約と同じように出さない。予約枠の種類を本
番APIでも識別する。
本番化時に詰める点
【要確認】本人を「最初に選んだ枠」に置くか「時刻順で１組目」に置くかを統一。現コードはownerKeyを
保持した後に時刻順に並べるため、逆順で枠を選んだケースを確認してください。
【要確認】名前による重複判定は体験版の方式です。本番では会員ID等も使って同姓同名を区別し、全組をま
とめて確保できるかをサーバーで判定します。
